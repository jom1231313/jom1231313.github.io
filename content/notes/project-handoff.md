## 실행되는 코드와 이어갈 수 있는 프로젝트

인수인계 문서는 다음 담당자가 처음으로 저장소를 열었을 때 필요한 순서로 작성하는 편이 좋습니다. 개발 환경, 설치와 실행, 빌드 확인, 배포 순서를 먼저 설명하고 화면 구조나 디자인 의도는 그다음에 연결합니다. 디렉터리 목록만 나열하는 것보다 “글을 추가하려면 어디를 수정하는가”처럼 작업 단위로 안내하면 실제 활용도가 높아집니다.

설치 명령에는 프로젝트에서 사용하는 패키지 관리자를 명시하고 잠금 파일을 함께 관리합니다. 환경 변수는 이름과 용도만 예시 파일에 적고 실제 비밀 값은 포함하지 않습니다. 브라우저에 공개되는 값인지 서버에서만 쓰는 값인지도 구분해야 합니다.

```text
시작하기
1. README에 명시된 Node.js 버전 준비
2. npm ci
3. .env.example을 참고해 로컬 환경 설정
4. npm run dev

전달 전 확인
- npm run build
- 콘텐츠 추가·수정 위치 확인
- 배포 계정과 도메인 관리 주체 확인
```

완료 기준도 문서의 일부입니다. 구현된 범위와 외부 서비스 연결이 필요한 범위를 구체적으로 기록합니다. 문의 폼이 브라우저에서 입력만 받는 상태라면 실제 전송이 된다고 설명하면 안 됩니다. 검증한 브라우저와 화면 크기, 남아 있는 제약을 적으면 운영 과정의 오해를 줄일 수 있습니다.

마지막으로 저장소 권한, 도메인 소유권, 서비스 결제 계정은 누가 관리하는지 확인합니다. 계정 비밀번호를 문서로 전달하는 대신 필요한 권한을 초대 방식으로 부여하고, 프로젝트 종료 시 접근 권한을 점검하는 과정까지 정해 둡니다.

- [ ] 새 환경에서 설치와 빌드가 가능한가?
- [ ] 일반적인 콘텐츠 수정 방법을 설명했는가?
- [ ] 구현 범위와 운영 책임자가 명확한가?

이 글은 스타터에 포함된 예시 글입니다.
